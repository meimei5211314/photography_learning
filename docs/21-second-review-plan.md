# 第二轮完善实施方案

## 直方图教学

新增 `histogram.js/css`，接口 `PhotoHistogram.mount(container,id)` / destroy，导出 `scenarios`（id/title/summary）供搜索；路由 `#histogram` 和 `#histogram/<id>`。四种固定原创合成分布：低调、高调、重要高光贴右、已通过试拍确认的亮暗取舍。用 SVG 柱状图与轴名、文字描述解释分布，不从双峰直接推断动态范围、不模拟真实 RAW 或提供虚假的精确 EV 恢复量。添加情境题、反馈和实拍入口，引用佳能官方播放信息和高光警告页。维持内容数量和备份版本不变。

## 图片实际可用性

`visual-practice.js` 增加 loading/ready/error 状态，以实际图片完成且 naturalWidth > 0 为依据；载入前和失败时阻止作答，错误给明确重试路径。加载回调必须属于当前渲染的图片，旧节点和离开页面的回调失效；避免每选一次答案便重新装载图片、丢失就绪状态。扩充单元测试和浏览器拦截请求的检查。

`editing-lab.js` 对全部原图/调整图核对就绪；单图失败持续提示，后续另一个图成功不能掩盖错误。修复时保留调整和顺序练习。

## 保存恢复与集成

根代理负责 app/index/search/README 及集成测试。保存结果驱动未保存标志；只有未保存的用户编辑才触发 beforeunload 提醒。新增“重试保存本页记录”按钮，不绕过 progress-store 的快照/冲突规则；初次读取被拒时先保留原始保护逻辑，不盲目覆盖未知记录。侧栏提示与状态一致。显式载入和导入仍需确认，失败不替换内存。

## 审查与验证

模块分工避免重叠编辑。计划先落地并提交，再实施。新增摄影事实对照佳能原始手册，保存来源说明。新增错误场景的浏览器检查与已有回归共同执行；图表检查 390px 窄屏、键盘操作、file://、来源链接、情境切换清理及搜索。验证发现缺陷先追加本节再修复。最后本地分步提交，构建版本与源码提交匹配。
