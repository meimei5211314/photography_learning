# 系统审查实施方案

先读 docs/26 需求。审查结果按全流程记录在 docs/28，保留依据与当前范围，最终验证在 docs/31。

## 内容与所有权

1. `shooting-depth-data.js`：新增阶段 8“准备与现场控制”，三课 `camera-readiness`、`filters-exposure`、`action-panning`。每课至少 6 个实质段落、5 个操作步骤、3 个误区、1 个情境题、两张卡和一个独立任务；分别讲拍前检查/记录介质与缓存、ND/CPL 条件与曝光对照、预判/连拍选择/追随。具体型号按官方资料，不盲目格式化、不将缓存与快门速度混淆。
2. `finishing-depth-data.js`：新增阶段 9“控制光线与成片”，三课 `still-life-lighting`、`local-editing`、`color-output`。分别补反光材质与光路、曲线/蒙版/处理取舍、色彩管理/软打样/打印验证。结构同上，不把网页滤镜称作实际 RAW/色彩管理软件，不要求付费软件或购买硬件才能阅读。
3. 最终 36 课、32 任务、72 卡。资料分别记录 docs/29、30；复用已有署名照片，仅作观察，不编造 EXIF。根代理对旧课做补充段落、相关路径和术语入口，保留旧检查项和 ID。
4. `learning-paths.js/css`：6 条按目标学习路径，导出 `PhotoPaths.items`、`mount(container,id,{data,state})`、`destroy()`。路由 `#paths`、`#paths/<id>`，列表及详情均仅一个 h1。每条路径给先修、课程顺序、任务、验收问题、交付证据与无相机时的限制；基于既有 state 统计阅读、自测答对、任务自报完成，不新增完成标记和存储格式。路径 ID 固定为 first-session、people-action、landscape-night、tabletop、editing-delivery、visual-story。
5. 根代理负责 app/index/search/README、课程阶段、媒体加载顺序、全站集成测试和备份兼容。路径代理负责浏览器回归、路径模块与相关测试。各内容代理仅写自己的新数据模块与来源/模块测试，不改共享文件或提交。
