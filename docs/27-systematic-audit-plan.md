# 系统审查实施方案

先读 docs/26 需求。审查结果按全流程记录在 docs/28，保留依据与当前范围，最终验证在 docs/31。

## 内容与所有权

1. `shooting-depth-data.js`：新增阶段 8“准备与现场控制”，三课 `camera-readiness`、`filters-exposure`、`action-panning`。每课至少 6 个实质段落、5 个操作步骤、3 个误区、1 个情境题、两张卡和一个独立任务；分别讲拍前检查/记录介质与缓存、ND/CPL 条件与曝光对照、预判/连拍选择/追随。具体型号按官方资料，不盲目格式化、不将缓存与快门速度混淆。
2. `finishing-depth-data.js`：新增阶段 9“控制光线与成片”，三课 `still-life-lighting`、`local-editing`、`color-output`。分别补反光材质与光路、曲线/蒙版/处理取舍、色彩管理/软打样/打印验证。结构同上，不把网页滤镜称作实际 RAW/色彩管理软件，不要求付费软件或购买硬件才能阅读。
3. 最终 36 课、32 任务、72 卡。资料分别记录 docs/29、30；复用已有署名照片，仅作观察，不编造 EXIF。根代理对旧课做补充段落、相关路径和术语入口，保留旧检查项和 ID。
4. `learning-paths.js/css`：6 条按目标学习路径，导出 `PhotoPaths.items`、`mount(container,id,{data,state})`、`destroy()`。路由 `#paths`、`#paths/<id>`，列表及详情均仅一个 h1。每条路径给先修、课程顺序、任务、验收问题、交付证据与无相机时的限制；基于既有 state 统计阅读、自测答对、任务自报完成，不新增完成标记和存储格式。路径 ID 固定为 first-session、people-action、landscape-night、tabletop、editing-delivery、visual-story。
5. 根代理负责 app/index/search/README、课程阶段、媒体加载顺序、全站集成测试和备份兼容。路径代理负责浏览器回归、路径模块与相关测试。各内容代理仅写自己的新数据模块与来源/模块测试，不改共享文件或提交。
6. `curriculum-support.js` 为原 12 节基础课补可观察的学习目标、建议先修与直接实拍任务入口，并为旧专题加入对应新课入口；app 在课程正文前展示这些信息。它们属于教学安排，不构成新的器材性能断言。课程阅读完成后保留“返回目标路径”入口，避免只按数组顺序浏览；路径以 URL 的查询参数携带上下文，刷新仍可恢复，不写入备份。

## 验证

- 从 0f9c3d0 冻结 30 课、26 任务、60 卡兼容契约，特别保护旧任务检查项顺序和存储语义。
- 全部课程/任务/卡片/路径唯一性、有效内部链接、资料来源、每课任务和图片匹配；原有行为测试继续运行。
- 浏览器遍历新课与路径，在桌面、390px、file:// 检查布局、搜索、深链、键盘、部分与完整记录状态、备份恢复后状态刷新。继续执行原有图片/存储异常回归。
- 目视新增课程和路径截图，构建后确认版本与最终 Git HEAD 一致。本地小步提交，不推送。

## 实施中发现与修正

后续验证缺陷先记录于此，再修改与重测。

- 路径的先修课同样需要返回原路径；仅允许核心课保留上下文会使补读后丢失目标。将明确列出的先修课纳入上下文校验，非成员课程和未知路径仍按普通课程处理，并验证先修课完成返回。
- 深链任务会滚动到目标卡，只有页面顶端返回链接不便使用。目标任务卡的记录按钮旁补返回当前路径链接，完成或写笔记后可直接检查路径状态，不必滚动回顶部。

- 路径先修复核发现首次拍摄路径直接进入 focus/modes，却未覆盖相应光圈与快门基础。将首次路径限定为 camera、camera-readiness、exposure、aperture、shutter、focus 六课，拍摄模式完整比较留给后续学习；验证路径课程顺序与任务入口，维持进度分项显示。
- 截图复核发现仅有两个任务的路径仍按三列预留空位，手机端课程顺序标题也过长。任务网格改为自动填满可用列，标题简化为“建议顺序：边读边验证”；重新检查两种宽度截图与卡内返回路径操作。

- 成片模块验证发现 `color-output` 引用了不存在的 `whitebalance` 媒体资产。改为已署名的 `streetNight` 夜街照片，并将观察提示明确对应暖灯、冷天空及暗部，不把它当作校准图或校样证据；模块测试遍历每课媒体 ID 与资产文件，全站媒体测试复跑。
